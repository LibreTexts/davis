# @libretexts/davis-docs-next

The next documentation site for Davis — **Astro + Starlight**, replacing the
Next.js/Markdoc site in `packages/docs`. See
[`rfcs/0001-documentation-platform.md`](../../rfcs/0001-documentation-platform.md)
for the decision record.

This is the **working prototype** for RFC Phases 1–3, proven on the `Button`
component plus the hand-authored `About` section.

## What it demonstrates

- **Live examples for both frameworks.** `src/content/docs/components/button.mdx`
  renders the real `@libretexts/davis-react` **and** `@libretexts/davis-vue`
  Button live, on the same page, via Astro islands. (A React-based Next.js site
  cannot live-render Vue.)
- **Self-documenting prop tables.** `scripts/generate-props.mjs` extracts prop
  metadata from component source (`react-docgen-typescript` + `vue-docgen-api`)
  into `src/generated/props.json`; `PropsTable.astro` renders it. The tables
  cannot drift — e.g. the `warning` variant and the `softDisabled` JSDoc appear
  automatically from source.
- **Overrides for edge cases.** `scripts/props.overrides.json` merges on top of
  generated data for types docgen can't fully resolve (e.g. Button's
  polymorphic `ButtonProps<C>` generic and default values).
- **Examples share their source.** `Example.astro` shows the exact file it
  renders (imported with `?raw`) — demo and code can't diverge.
- **Hand-authored narrative.** `src/content/docs/about/*` (principles, history,
  conventions) are plain Markdown, first-class alongside the generated reference.
- **Lighter runtime.** Static output → deploys to Cloudflare Pages as plain
  assets; built-in Pagefind search, dark mode, and sitemap.

## Develop

```sh
# Build the workspace packages the docs import (once, or after changes):
npm run build -w @libretexts/davis-core -w @libretexts/davis-react -w @libretexts/davis-vue

# Then, from this package:
npm run dev        # regenerates props, starts Astro dev server
npm run build      # regenerates props, builds static site to dist/
npm run typecheck  # astro check
```

`src/generated/props.json` is regenerated by `predev`/`prebuild` and is
git-ignored — never edit it by hand.

## Adding a component

1. Build the workspace packages if their source changed.
2. Add the component to the `COMPONENTS` list in `scripts/generate-props.mjs`.
3. Add live example islands under `src/examples/{react,vue}/`.
4. Write `src/content/docs/components/<name>.mdx` using `<Example>` +
   `<PropsTable>`, and add it to the sidebar in `astro.config.mjs`.
5. Add manual prop overrides only if docgen can't resolve a type.

## Migrating pages

`scripts/migrate-markdoc.mjs` is a codemod that converts the old Next.js
Markdoc pages to Starlight MDX:

```sh
node scripts/migrate-markdoc.mjs input select switch   # one or more slugs
```

It converts `{% framework-tabs %}`/`{% tab %}` → `<Tabs>`/`<TabItem>`,
`{% callout %}` → `<Aside>`, strips the stale "Coming Soon" Vue notices,
replaces the hand-written `## Props` tables with `<PropsTable>`, and drops the
redundant H1/dividers. Narrative prose and code examples are preserved. After
migrating, add each slug to `scripts/generate-props.mjs` and the sidebar, then
upgrade the key examples to live `<Example>` islands (see any Forms page).

## Status

Migrated so far: **Button** + the full **Forms** group (Checkbox, Combobox,
Form Section, Input, Input Group, Listbox, Number Input, Radio Group, Select,
Switch, Textarea) — 12 components, all with generated prop tables **and** a live
`<Example>` island (React + Vue) in their Basic Usage section, including the
compound Combobox/Listbox and the InputGroup/FormSection wrappers. Later
sections still show static code examples (now Vue-accurate) until they're
upgraded.

Remaining work (tracked in the RFC): migrate the other component groups + table
packages, upgrade the remaining per-section examples to live islands, wire CI
(build + docgen + link-check + story/docs coverage), publish Storybook as the
linked workshop, add redirects, and retire `packages/docs`.
